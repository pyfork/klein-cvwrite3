# Slice S-007: the three web fonts are served as woff2 files cut to the Latin letters, so that every page loads about a quarter of today's font bytes.

Feature: [brief](brief.md)
Slice: 7 of redesign

## Outcome
The three web fonts are served as woff2 files cut to the Latin letters, so that every page loads about a quarter of today's font bytes. Today every page loads three whole variable TrueType files, 524,216 bytes uncompressed (Schibsted Grotesk 176,068, Libre Caslon Text italic 176,200, Geist Mono 171,948). The positive control's cut (woff2, Basic Latin, Latin-1, Latin Extended-A and the punctuation the app uses; in the slice-plan PR's description) came to 150,244 bytes; the build measures its own. The letters keep their shapes and the weight range stays whole, so every page looks as it does today. The kept set covers English and Malay and names with Latin accents (é, ñ, ł, ş); a letter outside it falls back to the next font in the stack, as letters the fonts never had do today.

## Rules

AC-178 Given the stylesheet,
      when a page asks for Schibsted Grotesk, Libre Caslon Text (italic) or Geist Mono,
      then that face's one `src` is `url(/fonts/<name>.woff2) format("woff2")`, with the family, style, weight range and `font-display: swap` it has today; and the file is served with status 200 as `font/woff2`, also on a machine whose type table does not know `.woff2` (Python 3.10's built-in table does not), as slice 5 did for `.webp`.

AC-179 Given each of the three woff2 files and the TrueType file it is cut from (which stays in `fonts/`, unchanged, with its licence),
      when they are compared,
      then the woff2 holds exactly the source's characters that fall in the kept set, `fonts/web-subset.txt`; each of those characters draws the same outline as in the source; and the weight axis is the source's (same range and default). The kept set holds at least U+0020 to U+007E, U+00A0 to U+017F, and every character the app's own text uses that the source has.

AC-180 Given the three woff2 files,
      when their sizes are read,
      then each is at most 60,000 bytes and the three together at most 160,000 bytes (the fonts' phone budget; going over is a re-plan). A file of 60,001 bytes or three totalling 160,001 fail; at exactly the limit they pass.

AC-181 Given the full test suite on any later PR,
      when the app's own text (the templates, `app/content/`, `app/i18n.py`, and the stylesheet and scripts in `app/static/`) uses a character that a web font's source has and the kept set does not, or the woff2 files go over the budget in AC-180,
      then the suite fails and names the character (with its code point and the file it is in) or the file and its size; a character the source does not have (such as ✓) is not its business, because the page falls back for it today. The test uses only the standard library.

AC-182 Given the same app,
      when anything else is served,
      then it is as before this slice: `.css`, `.js`, `.webp` and `.ttf` answer as before, the stylesheet and script keep their types, the three source TrueType files are byte for byte unchanged, and the CV fonts the PDF render reads are untouched.

## Out of scope
- **Taking the source TrueType files out of `fonts/`:** they are the source of the cut and stay; nothing links them after this slice; safe because a file nothing links is never sent; revisit if `fonts/` is ever cleaned up.
- **`unicode-range` in the `@font-face` rules:** each face has one file, so there is nothing for a browser to choose between; safe because a missing letter falls back either way; revisit if a face is ever split into more than one file.
- **The CV fonts** (Archivo, Manrope, Source Serif 4, IBM Plex Mono) and the PDF render: they are embedded in the PDF, not sent to a browser.
- **Server compression:** not checked whether sk24's nginx or Cloudflare compresses `.ttf` today; woff2 is compressed inside the file, so the budget holds either way.
