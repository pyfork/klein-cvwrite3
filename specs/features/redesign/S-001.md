# Slice S-001: When anyone opens a page of the app, they see it in the new look (light theme).

Feature: [brief](brief.md)
Slice: 1 of redesign

## Outcome
When anyone opens a page of the app, they see it in the new look (light theme).

## Rules

AC-1  Given any page the app serves, requested in the state it needs (signed out for the public pages, signed in for the rest),
      when it renders,
      then its HTML links `/static/betterjobs.css?v=<app version>` and does not link `calm.css`.

AC-2  Given the stylesheet URL with the running app's version,
      when it is requested,
      then the answer is 200 and not `no-store`; and `/static/calm.css` is no longer served (404).

AC-3  Given the app's version changes,
      when a page renders,
      then the stylesheet URL carries the new version, so an old cached stylesheet never meets new markup.

AC-4  Given the class names the templates use,
      when the stylesheet is read,
      then every one has a rule in it, except hooks the check lists by name, each with its reason.

AC-5  Given the fonts the stylesheet declares,
      when each `@font-face` source is followed,
      then it is a file in the app's `/fonts` mount that exists and is served (200), and the licence file of its family is in `fonts/`.

AC-6  Given any page and the stylesheet,
      when they are read,
      then neither asks another host for a stylesheet, script, font or image (no `href`, `src`, `url()` or `@import` to another host for these). Anchors to other sites are links, not requests, and are not affected.

AC-7  Given the CV PDF render,
      when this slice lands,
      then every font file the render names is still in `fonts/` unchanged, and a CV renders with the same page count, fonts and text hash as before.

AC-8  Given a signed-in user, and then a signed-out visitor,
      when any page renders,
      then the shell still holds what the brief's Shape lists for it: the skip link to `#main`, the balance with its expiry, the nav (two steps, three tabs, Admin for the owner), the pause or slow banner, the CV bar, and the footer (report a problem, notice, terms, sign out, version).

### Look: tokens, type, shape

AC-9  Given the stylesheet,
      when its `:root` token block is read,
      then it holds these colours at these exact values: ground `#F2F1ED`, slab `#FFFFFF`, ink `#13233A`, coral `#FF5A47`, photocopy grey `#D6D4CE` with its ink `#5A585E` (Addendum 14); teal `#26968A`, marigold `#F3B43C` and sky `#A0CDEC` (the accepted collage v2); and the designer's additions: quiet slab `#F7F6F2`, muted text `#6A7586` on white slabs and `#566275` on the ground and on the quiet slab, secondary ink `#3A4960`, coral for text `#C2382A`, error red `#B42318`, field edge `#7D8798`, hover tint `#E6E5E0`, and the four status tints in pattern Status note.

AC-10 Given the stylesheet outside its token block,
      when it is read,
      then it holds no colour literal (`#rrggbb`, `rgb()`, `rgba()`, `hsl()`), so the dark slice overrides tokens and nothing else; the only literals allowed are the strokes and fills inside SVG icons in `url("data:image/svg+xml…")`, which cannot read a token, and the check lists them by name.

AC-11 Retired 2026-10-29 by slice 2 (dark mode, S-002 AC-72 to AC-75), as slice 1's plan said. It read: on a dark device the page looks as on a light one, with `color-scheme: light` and no `prefers-color-scheme` rule.

AC-12 Given any page,
      when its font families are read,
      then headings and text use Schibsted Grotesk; only `.note` uses Libre Caslon Text italic; only labels and codes (`.eyebrow`, `.kicker`, `.badge`, `.chip`, `.opt`, `.s-time`, `.pass`, `code`) and the CV text box `#cvtext` use Geist Mono; and each stack ends in a system fallback (Helvetica Neue, Arial, sans-serif; Georgia, serif; ui-monospace, Menlo, monospace).

AC-13 Given the stylesheet,
      when it is read,
      then no rule names Manrope, Source Serif 4, IBM Plex Mono or Archivo, and the body class `opt-calm` is gone.

AC-14 Given any page while its fonts are loading, or when every request to `/fonts` fails,
      when it renders at 320 and 390,
      then the text shows at once in the fallback stack (every `@font-face` has `font-display: swap`) and nothing overlaps or is clipped.

AC-15 Given any page at any width from 320 to 1440,
      when computed text sizes are read,
      then they follow pattern Text size: sentence text and controls 16 px or more, labels 14 px or more, inputs 16 px or more, body 17 px, h1 28 px at 320 rising to 40 px at 768, and the only text that changes size with width is the headings.

AC-16 Given every text colour and the background it sits on in the stylesheet,
      when each pair's contrast is computed,
      then every pair is 4.5:1 or more, and the check lists these pairs: ink on ground, slab, quiet slab and each status tint; muted on ground, slab and quiet slab; secondary ink on ground and slab; coral for text on ground and slab; white on ink and on error red; ink (never white) on coral; `#5A585E` on `#D6D4CE`.

AC-17 Given the field edge, the focus ring and the status icons,
      when each is measured against the colour behind it,
      then each is 3:1 or more.

AC-18 Given any page that is shorter than the window,
      when it renders at any width,
      then the ground colour fills the whole window (both `html` and `body` set it), with no white band below the footer and none on overscroll.

AC-19 Given any page at 1280 and at 1440,
      when it renders,
      then the column holding the header, banners, page and footer is centred and 880 px wide at most (gutters 16 px below 768 and 24 px from 768 inside that width), with ground on both sides.
      Named exception to "content grows to 1280": every old page is one column of forms, text and tables built for a narrow measure, and a wider column would stretch inputs and lines past easy reading. A page slice may widen its own page with a rule of its own.

AC-20 Given any `.card`,
      when it renders,
      then it follows pattern Slab: white, 24 px radius, `--shadow`, padding 20 px below 560 and 28 px from 560, and the blocks in `.page` are 20 px apart.

AC-21 Given the stylesheet,
      when it is read,
      then it has no `gradient(`, no `backdrop-filter` and no `blur(`, and `--shadow` is the only shadow slabs and pills use, so Calm's gradient on `.result-head` is gone and every block stays flat paper.

### The header: brand, balance, nav

AC-22 Given a signed-in user at 840 px or wider,
      when any page renders,
      then the header has two rows: row 1 holds the brand at the left of the column and the balance at the right; row 2 holds the nav rail in one line (pattern Page nav): the two steps, a 1 px divider, the tabs, and Admin last for the owner.

AC-23 Given a signed-in user from 480 to 839 px,
      when any page renders,
      then row 1 is as at 840, and the rail has two lines: line 1 the two steps, half the width each; line 2 the tabs (Admin last), each growing so the line is filled edge to edge.
      Below 840 the rail goes to two lines, because the owner's six 44 px items with 8 px gaps need about 700 px in one line and the column leaves too little margin for the longest labels.

AC-24 Given a signed-in user below 480 px,
      when any page renders,
      then the balance takes its own row under the brand, the full column width and left-aligned, with its two lines intact; and the tabs wrap onto a further line when they do not fit (for the owner at 320: Applications and Credits on one line, Account and Admin on the next).
      Below 480 the balance moves under the brand, because the pill needs about 200 px and the brand about 160, which is more than the 288 px a 320 px phone leaves.

AC-25 Given any width from 320 to 1440 and any of: a user, the owner with an account, the owner alone,
      when the header renders,
      then every nav label is fully visible, nothing in the header scrolls (the rail's `scrollWidth` equals its `clientWidth`), clips or ends in an ellipsis, no link sits behind a menu button, and the page does not scroll sideways.
      This replaces Calm's nav, which scrolled sideways and hid the step numbers below 560 px.

AC-26 Given any width,
      when the header renders,
      then what the person sees from top to bottom and left to right (brand, balance, steps, tabs) is the order Tab visits them; no CSS `order` or absolute position moves a control out of source order.

AC-27 Given any page,
      when the header renders,
      then the brand is a link to `/` named "Better Jobs home", with a 24 px scrap mark before the wordmark "Better Jobs" (22 px, weight 800, one weight for both words); the mark is coral, tilted −6°, drawn in CSS with `clip-path: polygon(8% 14%, 92% 2%, 100% 70%, 70% 98%, 4% 88%)`, and is no image file; the link is 44 px high at least.
      The mark is coral, as in the target (re-plan 2026-10-29, the owner's approved row in README-brief-amended.md; Addendum 14's coral list gains the brand mark).

AC-28 Given a page that renders with the `signed-out` body class,
      when the header renders,
      then it shows the brand alone: no nav and no balance appear, and no empty rail or pill is drawn, whether or not a session exists.

AC-29 Given the nav,
      when a page sets its section,
      then exactly the one link with `aria-current="page"` is an ink pill with white text (15.8:1), no other link has that fill, and a page whose section matches no link marks none.

AC-30 Given the two steps,
      when the nav renders at any width,
      then each shows a 24 px circle before its label, with its number (1, 2) or, for Profile once the profile is ready, a tick (screen readers still hear "(done)"); the circle is outlined in ink, and on the current item it flips to a white fill with an ink mark.

AC-31 Given a user whose profile is not ready, or whose balance is 0,
      when the nav renders,
      then every link is a normal enabled link in the normal style: none is greyed, hidden or marked disabled, and Generate is a plain link before the profile is ready (the page says what is missing, Addendum 10).

AC-32 Given the owner,
      when the nav renders,
      then Admin is the last item and carries a 24 px marigold circle with an ink "A" before its label.

AC-33 Given a signed-in user,
      when the balance renders,
      then it follows pattern Balance: one link to `/credits`, two lines (count and unit, with "· N in use" muted when N is above 0; then "earliest expire D Mon YYYY" or "buy more"), both lines visible at every width from 320, the whole pill a target of 44 px or more. Today's words do not change.
      Calm hid the second line below 560 px; it now stays, because the expiry is what the brief says the balance shows.

AC-34 Given a balance of 0, of 1, or with credits in use,
      when the balance renders,
      then the pill keeps its shape and colours: no red, no icon, no pulse. A balance of 0 reads "0 credits" over "buy more". The page, not the shell, tells the person what to do next.
      A credit held by a CV in progress is "in use", never "out of credits" (Addendum 10).

### Banners

AC-35 Given the pause banner or the slow banner,
      when it shows,
      then it is a Status note of kind warn, the full column width, directly under the header, its words wrapping over as many lines as they need, with no close control and no animation; the longest real text (the pause text with its "Paused since" tail, about 200 characters) shows in full at 320 with no clipping, no scrolling and no fixed height.

AC-36 Given a CV being written or a finished CV not yet opened,
      when the CV bar shows,
      then it is a Status note of kind info reading "A CV is being written:" or "Your CV is ready:", the title in bold, then the link "Open it"; the title wraps and breaks inside a long unbroken word (up to 200 characters); "Open it" is bold, underlined and 44 px high at least, with 8 px from the text before it.

AC-37 Given neither banner nor CV bar,
      when a page renders,
      then nothing is drawn between the header and `main`: no empty strip and no border, and `main` starts 24 px below the header.

AC-38 Given both a pause or slow banner and a CV bar,
      when a page renders,
      then the pause or slow banner is above the CV bar, the two are 8 px apart, the banners start 12 px under the header, and `main` starts 24 px below the last one.

AC-40 Given the Sign out button,

### Keyboard and focus

AC-43 Given any page,
      when a keyboard user presses Tab once,
      then focus lands on the skip link before any other control, and it appears: an ink pill with white 16 px bold text, 44 px high at least, at the top left of the column, above all other content; when not focused it is out of sight. Enter moves focus to `#main`, which shows no ring (it is not a control), and the next Tab reaches the first control inside it.

AC-44 Given any link, button, input, select, textarea, `summary`, checkbox or radio,
      when it takes keyboard focus,
      then it shows the pattern Focus ring: 3 px solid, 3 px outside the edge; coral where a white slab is behind the ring, ink on the ground, on the quiet slab and on a coral button (re-plan 2026-10-29, the owner's approved row in README-brief-amended.md); a field also takes a 2 px ink edge and the halo; no `outline: none` stands without that replacement.

AC-45 Given the controls in pattern Touch target (brand, balance, nav items, banner link, footer links, Sign out, buttons, choice rows, `summary`, packs, drop zone, the language links),
      when each is measured at 320, 390 and 1280,
      then it is 44 by 44 px or more with 8 px or more to its neighbour; and a link inside a sentence is the one named exception to the height, for the reason in that pattern, with the language links on the notice and consent pages not exempt.

### States: hover, press, disabled, motion

AC-46 Given a pointer that can hover,
      when it is over a button, a nav item, a pack or the drop zone,
      then the control takes its hover style (pattern Hover and press), and every hover rule sits inside `@media (hover: hover)`; nothing is shown only on hover, and no information is only in a `title` tooltip (the balance's "Your balance" tooltip adds nothing its visible text lacks).

AC-47 Given a touch or a mouse press on a button, a nav item, a pack or the drop zone,
      when `:active` applies,
      then the control shows the press style (scale 0.98, or the hover-tint fill for the drop zone), so a touch gets the feedback a mouse gets from hover.

AC-48 Given a disabled button, pack or field (for example the packs while buying is closed),
      when it renders,
      then it is at 45% opacity with a not-allowed cursor, takes no focus, and shows no hover lift and no press scale; a disabled main button stays coral at that opacity. The note that says why (the Generate page's `#gen-why`, the pack panel's "Buying is paused" note) is never dimmed: it stays at full contrast beside the control, because Addendum 10 says a blocked Generate says why, at the button.

AC-49 Given the stylesheet,
      when it is read and when a page is used,
      then it has no `infinite` animation and no keyframe pulse (the running step no longer pulses), and every transition is 300 ms or less on transform, opacity or colour.

AC-50 Given a device set to reduced motion,
      when any page is used,
      then every transition and transform is off, a state changes at once, and each state still shows.

## Out of scope
- **Dark mode:** the next slice. Until it lands the app shows the light theme on every device, as Calm does today.
- **Scripts and their allow-list test:** their own slice. This slice adds no script, so the Screens line of `docs-public/project-rules.md` is not needed yet. That line also names `calm.css`; the owner's own PR for it renames it.
- **The art, its generator and any torn-edge image mask:** their own slice. If the designer rules the shell needs a torn edge, it is drawn in CSS or inline SVG with no image file; otherwise it waits.
- **Every page's own markup.** The old class names stay; each page slice drops its own.
- **The signed-out home** and the `/` change.
- **The CV PDF style, the emails, the privacy notice and consent text.**

## Touch points
- `app/static/betterjobs.css` (new), `app/static/calm.css` (deleted).
- `app/templates/base.html`: the stylesheet link, the body class, the shell markup. No other template.
- `fonts/`: the new font files, each family with its licence file; the existing files stay. The files are fetched once, with the owner's OK for each download (file, source, size).
- `tests/test_ux.py` and `tests/test_oneshot.py`: the two tests that pin the old stylesheet's name.
- `CHANGELOG.md`: one line.
