# Slice S-005: The home's cut-paper art exists in `app/static/art/`, made by a seeded generator in `gen/`, so that the signed-out home (slice 6) can show it.

Feature: [brief](brief.md)
Slice: 5 of redesign

## Outcome
The home's cut-paper art exists in `app/static/art/`, made by a seeded generator in `gen/`, so that the signed-out home (slice 6) can show it. Addendum 14 asks for the art as static WebP files, made by a script in the repo (OpenCV, seeded, so a rerun gives the same files). The design spike's generator makes 25 images; the accepted homepage v2 uses 20 of them, one of them a PNG mask (the torn edge).

## Rules

AC-89 Given the repo,
      when `app/static/art/` is listed,
      then it holds exactly the 20 images the home uses, each a WebP with an alpha channel and no wider than 2,400 px: `ad-lilac`, `ad-marigold`, `ad-teal`, `arrow`, `clipping`, `copy`, `cv-lilac`, `cv-marigold`, `cv-teal`, `edge`, `folder`, `ground`, `pages`, `redacted`, `scissors`, `scissors-ink`, `scrap-dot`, `scrap-star`, `scrap-tri`, `spotlight` (each `.webp`). The torn edge is a WebP too. No other file is in the folder.

AC-90 Given the app,
      when anyone asks for `/static/art/<name>.webp`,
      then it is served as `image/webp`, cached like the other `/static/` files (no `no-store`), with no sign-in. The art is public and holds no personal data, so there is no owner and no 404 rule for another user. The folder weighs at most 600,000 bytes in all and each file at most 100,000 bytes.

AC-91 Given `gen/collage.py`,
      when it runs with no argument,
      then it writes exactly the 20 files of AC-89 into `app/static/art/`, listed in its module-level tuple `NAMES`. Every random draw comes from a seeded generator (no call to `default_rng()` without a seed, no `random`, `time` or `datetime` module), so a rerun with the pinned packages on the same machine writes the same bytes. Its docstring says how to run it.

AC-92 Given `gen/requirements.txt`,
      when it is read,
      then it pins `opencv-python-headless`, `numpy` and `pillow`, each with `==` and its `--hash=sha256:` lines, and nothing else; the docstring installs it with `--require-hashes --only-binary :all:`. These packages stay dev-only: `requirements.txt`, `requirements.lock`, `requirements-dev.txt` and the workflows under `.github/` name none of them and not `gen/`, and no Python file in `app/`, `render/`, `checks/`, `scripts/` or `tests/` imports `cv2`, `numpy`, `PIL` or `gen`.

## Out of scope
- **Showing the art on a page, and its `?v=` key:** the home (slice 6) loads it. No template changes here, so the app version stays and the stand-in pages under `acceptance/screens/` need no new baselines.
- **The other 5 images of the spike** (coins, magnifier, gap, a lilac blob, a sky strip): the home does not use them; safe because the generator can add them back; revisit when a page slice needs one.
- **Regenerating the art in CI:** the Shape's key choice. OpenCV output can differ by version and platform, and CI never installs the generator's packages. The build PR attaches a local run instead: two runs, and the committed files, byte for byte.
- **The daily OSV scan of `gen/requirements.txt`:** the sweep reads `requirements*.lock` files only, and these packages never reach the server; revisit if the generator ever runs anywhere but a developer's machine.
- **The fonts' weight and the home's phone budget:** slice 6 (the plan's Owed list).

## Touch points
- `gen/collage.py`: new, moved from the design spike; trimmed to the home's 20 images, the torn edge written as WebP, `app/static/art/` as the default folder.
- `gen/requirements.txt`: new, the three pins with their hashes.
- `app/static/art/`: new, the 20 WebP files the generator writes.
- `CHANGELOG.md`: one line.
- Nothing the app runs changes: no template, script, style, route or font, so `app/main.py`'s `APP_VERSION` stays.
