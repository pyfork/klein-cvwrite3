# Slice S-002: When a person's device is set to dark mode, every page of the app opens in the dark theme.

Feature: [brief](brief.md)
Slice: 2 of redesign

## Outcome
When a person's device is set to dark mode, every page of the app opens in the dark theme; on a light device nothing changes.

## Rules

AC-72 Given a device set to dark mode,
      when any page renders,
      then `:root` declares `color-scheme: light dark` and the dark token values apply; native controls and scrollbars follow the theme.

AC-73 Given a device set to light mode, or a browser that reports no preference,
      when any page renders,
      then every token has its slice-1 value (AC-9) and the page looks as it did before this slice.

AC-74 Given the stylesheet,
      when its dark-mode rules are read,
      then they sit in `@media (prefers-color-scheme: dark)` and set custom properties (tokens) only, no other property; AC-10 still holds (no colour literal outside the token blocks).

AC-75 Given the theme,
      when a person wants to change it,
      then it follows the device setting only (Addendum 14): there is no switch, no cookie, no stored choice and no script for it.

      when any page renders,
      then these tokens take v2's dark values (app name = v2 name where they differ):

      Buttons that use `--ink` as fill and `--slab` as text invert with them, as v2's pill does (light fill `#F2EEE6`, navy text; 13.75:1).

AC-78 Given a device set to dark mode,
      when any page renders,
      then these keep their light values, as v2 keeps them: `--coral` `#FF5A47`, `--teal`, `--marigold`, `--sky`, the fonts, `--ease`, `--mark-tick` and `--mark-cross` (white on teal, 3.61:1).

AC-79 Given text or an icon on coral or marigold (the primary button, the admin tab's marker),
      when any page renders, in either theme,
      then it uses a new token `--on-accent: #13233A`, set once in `:root` and never in the dark block (v2's `.pill.coral` keeps navy text): 5.12:1 on coral, 8.58:1 on marigold. Today these use `--ink`, which in dark would give 2.67:1 and 1.59:1. The light look does not change (`--ink` is `#13233A` there).

AC-80 Given a device set to dark mode,
      when the QR code, or any paper or CV preview a later slice adds, renders,
      then it stays light (Addendum 14): the QR frame uses a new token `--qr-ground: #FFFFFF`, set once in `:root` with no dark value, so the code scans; a paper or CV preview uses v2's `--paper` tokens, which have no dark values.

AC-81 Given a device set to dark mode and a keyboard user,
      when an element has focus,
      then the ring is coral (the target) on the ground (5.87:1) and on slabs (5.16:1 on `--slab`, 4.73:1 on `--slab-2`); on a coral button it stays `--ink`, offset onto the ground (15.67:1), as S-001 AC-44 does. The light split of AC-44 is unchanged.

AC-82 Given a device set to dark mode,
      when any page renders,
      then every text pair meets 4.5:1 (AC-16) and every border, ring and status mark meets 3:1 (AC-17), as measured in AC-76 to AC-81. Lines that only divide (`--grey` rules, table borders) are decoration and carry no floor, as in light.

AC-83 Given a device set to dark mode,
      when every page is opened at 320, 375, 768, 1024, 1280 and 1440 px, in each state the light pages show (empty, filled, error, alert, disabled, focus),
      then only colour changes: layout, wrapping and sizes match the light page at the same width; no horizontal scroll; no surface keeps a light background except AC-80's; the page background is dark from the first paint (`html` and `body` use `--ground`).
